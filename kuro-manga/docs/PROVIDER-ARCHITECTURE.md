# Provider architecture and extension contract

The original source has a compiled Expo/Metro web export with no editable original React source. Its exact bundle hash is pinned by `scripts/build-catalogue.mjs`. `client/catalogue-core.mjs` wraps only known Metro module factories before application startup; the original export remains byte-identical. This prevents late hook replacement and makes new provider identities valid on initial deep links.

Factory boundaries: 789 sourceManager, 784 settings, 1706 series identity, 790 exact chapter dedupe, 794 edition grouping, 870 pagination merge, 791 search merging, 1342 Home placement, 875 MangaDex identity links, 1389 readiness, 1388 ready collections, and 1595 active page/query credits. All private Auth/profile modules stay outside this factory allowlist.

Adapters supply `id/name/version/color/capabilities`, search/searchPage, popular/latest, details, chapter list and page manifest methods. `capabilities.readable:false` excludes metadata/external catalogues from reading. Provider IDs must be lowercase alphanumeric because the original reader splits chapter IDs at `-`/`:`. IDs are `provider-<series>` and `provider:<chapter>`; route and server decoding validate them. Search pages contain `{items,nextPage?,total?,notice?}`. Chapter lists are newest first with numeric decimal chapter numbers and real timestamps or zero when unknown.

Server modules are separate: `policy.mjs` is the audited origins/capability map, `transport.mjs` pins public IPv4 DNS and bounds requests, adapters reconstruct canonical data, `parameters.mjs` normalizes actual operation inputs, `cache.mjs` coordinates shared cache/rates/locks, `images.mjs` validates and bounds delivered bytes, `tickets.mjs` authenticates provider/chapter/group/URL/expiry, and `routes.mjs` controls the same-origin API. Catalogue Redis uses its own namespace; no reading images or user account data are persisted there.

Only a fixed adapter can issue a page manifest. The POST compatibility endpoint takes provider and chapter ID only. Every original reader's page loading now resolves through the canonical backend while its original browsing, chapter identities and history remain. MangaDex page URLs come from its at-home API and group credits from its chapter API; excluded groups remain blocked for previously issued tickets.

The core keeps readiness checks keyed by generation plus series. Refresh invalidates a generation; obsolete in-flight success cannot repopulate current readiness. Hook installation happens before first render. Pagination keeps full raw source records; grouping is applied in the display layer so alternate editions and the Ungroup option survive. Reader credits follow the active query's chapter, including cached prefetch and local Next chapter navigation.

`dist/catalogue-bridge.js` retrieves current public configuration, mounts the directory and controls targeted visible-app refresh. The separate daily cron function refreshes server feed adapters, with private bearer authentication. Vercel rewrites and explicit registry bundling are in `vercel.json`.

To add a provider: establish its current primary HTTPS site and public access conditions; implement its DTO/IDs/search/pagination/chapters/pages; add exact permitted origins from real canonical sample manifests; add fixtures and live sample checks; record failures honestly; update the static registry and rebuild the bootstrap. Never add an arbitrary URL proxy, forward login cookies, evaluate downloaded scripts or declare readability without actual image evidence.
